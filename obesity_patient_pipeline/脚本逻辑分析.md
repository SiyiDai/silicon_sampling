# 脚本逻辑分析

## 已阅读脚本

- `context_generation.py`：读取Qualtrics风格CSV/XLSX，将少量种子题转成persona上下文；只输出指定种子列。
- `data_generation.py`：两阶段LLM流程，先生成persona profile，再让persona回答剩余题目；包含API key读取、OpenAI client、JSON解析兜底。
- `data_processing.py`：逐行运行persona生成和作答，保存预测、真实答案、原始模型响应，并计算exact match。
- `real_individual_pipeline/context_generation.py`：升级为兼容普通CSV和Qualtrics导出的读取器；增加缺失值处理和CFPS个人字段作为种子。
- `real_individual_pipeline/data_generation.py`：把persona概念改为digital individual，强调缺失值保持未知，输出summary、response_style、stable_patterns、uncertainty_notes。
- `real_individual_pipeline/data_processing.py`：沿用两阶段处理，并把目标问题从除种子列外的所有字段中构建。
- `real_individual_pipeline/questionnaire_generation.py`：完整问卷作答runner雏形，包含硬编码短问卷、两阶段调用、token日志、prompt日志、答案规范化和show_if处理。
- `data/persona_seed/sample_complete_3600.py`：过滤英文BMI样本完整案例并抽样3600。
- `data/persona_seed/create_english_bmi_dataset.py`：从CFPS BMI数据生成英文分析CSV，做省份、性别、工作、运动等字段翻译。
- `data/persona_seed/tools/inspect_sources.py`：检查CFPS字段、疾病编码表、问卷docx文本和表格。
- `data/persona_seed/tools/build_obesity_persona_dataset.py`：严格按问卷可观测条件构建肥胖患者候选池和210样本；当前口径不再用任意疾病编码补足超重组。
- `data/persona_seed/tools/audit_cfps_filter_funnel.py`：审计筛选漏斗，说明为什么原始超重人数很多，但叠加学历、收入代理、问卷相关合并症后不足135。
- `data/persona_seed/tools/build_selected_210_chinese_eda.py`：清洗210样本、生成汇总表、SVG图表、Markdown报告和自包含EDA notebook。
- `data/persona_seed/tools/run_obesity_questionnaire_pilot.py`：现有肥胖问卷10人试跑脚本；支持API、dry-run、offline-baseline、背景/无背景双版本。
- `data/persona_seed/tools/build_questionnaire_pilot_notebook.py`：读取10人试跑结果和离线基线，生成问卷试跑分析notebook。

## 现有逻辑抽象

已有脚本的核心不是一次性直接答题，而是“两阶段受访者模拟”：

1. 从真实/清洗数据构建受访者种子上下文。
2. 用 `PROFILE_SYSTEM_PROMPT` 生成稳定的数字画像。
3. 用 `QUESTIONNAIRE_SYSTEM_PROMPT` 和完整问卷题目让画像作答。
4. 保存结构化答案、逐人prompt、原始response、token和耗时日志，便于复核。

## 本文件夹采用的改动

本文件夹保留上述两阶段结构，但替换成更严格的肥胖患者问卷版本：

- 默认输入改为 `肥胖患者210样本_清洗与EDA_中文/清洗后_210样本.csv`。
- 问卷模板使用 `questionnaire/obesity_patient_questionnaire_template.py`，不是旧的短问卷。
- `context_generation.py` 明确拆分硬事实、严格筛选口径、不可直接判定字段。
- `prompt_config.py` 更新 `PROFILE_SYSTEM_PROMPT` 和 `QUESTIONNAIRE_SYSTEM_PROMPT`：
  - 硬事实不得改写。
  - 城市线级、家庭总收入、既往减重措施、GLP-1经历等只能模拟推断。
  - 背景信息只能影响产品/竞品认知语境，不能改变CFPS事实。
  - 作答必须遵守show_if、选项编码和问卷answer_format。
- `run_dual_version_questionnaire.py` 复用已测试的基础runner，但覆盖prompt和context builder，并默认生成两个版本：`含背景信息` 与 `不含背景信息`。

## API安全说明

我没有运行任何会调用API的脚本。`run_dual_version_questionnaire.py` 默认是为你运行准备的；如需只检查文件和prompt而不调用API，可加 `--dry-run` 或 `--offline-baseline`。
